# VibeForge — план роботи

## Де ми зараз (готово)

- **Веб-застосунок працює end-to-end**: React-чат зліва → FastAPI-бекенд → Gemini генерує повний HTML → живий прев'ю в iframe справа
- **Акаунти** (Supabase): вхід через Google або email + пароль з 6-значним кодом на пошту (лист від `vibeforge.verify@gmail.com`), «Forgot password?» з кодом. Генерувати можна лише після входу
- **Проєкти в базі Supabase**: у кожного користувача свої, не зникають при перезапуску Render
- **Ліміт 5 генерацій на день на користувача** (`backend/app/usage.py`, таблиця `generations`), скидається опівночі за Києвом; лічильник «N of 5 left» під чатом
- **Реальна AI-генерація** через безкоштовний рівень Google Gemini API
  - **Ланцюжок моделей** (`backend/app/generation/gemini.py`): 3.8 → 3.7 → 3.6 → 3.5 → 3 Flash → 3.5 Flash Lite → 3.1 Flash Lite. Ліміти окремі для кожної моделі (Flash — 20/день, Flash Lite — 500/день), разом ≈ 100 якісних + ≈ 1000 простіших генерацій на день на весь сайт
  - Перевантажена (503), вичерпана чи прибрана Google (404) модель тимчасово пропускається
  - Окремі повідомлення для особистого ліміту і для загального ліміту Google
  - Системний промпт забороняє localStorage/cookies, вигадані шляхи до картинок, посилання на неіснуючі сторінки, і просить завершений сучасний дизайн
- **Ітеративне редагування**, **галерея проєктів**, **завантаження HTML**
- **Сторінки `/privacy` і `/terms`**; вхід через Google опубліковано для всіх (статус «In production»)
- **Тести**: `backend/.venv/bin/pytest` (20 тестів: ланцюжок моделей, API, ліміт, неблокуючий сервер)
- **Опубліковано**: фронтенд на Vercel (`vibe-forge-swart.vercel.app`), бекенд на Render (`vibeforge-e0p3.onrender.com`). Пуш у `main` = одразу продакшен

**Відомі обмеження:**
- Тільки **статичні односторінкові сайти** — свідомий вибір MVP
- Одна генерація триває ~1–3 хв; удень Flash-моделі часто перевантажені (кожна відмова 503 приходить за 20–30 с), тоді сайт робить Flash Lite
- Render засинає після ~15 хв бездіяльності — перший запит після паузи ~50 с
- Листи з кодами йдуть через Gmail (≈ 500/день) — без власного домену частина може потрапляти в спам

## Можна будь-коли (не впливають на дизайн)

- Плавне оновлення сервера: зараз викладання нової версії обриває генерації, що йдуть у цю мить (налаштувати очікування в Render + uvicorn)

- Автоматичні перевірки на GitHub перед викладанням (CI)
- Окрема тестова база Supabase для розробки (зараз локальна розробка пише в ту саму базу, що й живий сайт)
- Sentry (помилки користувачів) і аналітика — перед будь-якою рекламою
- Розібратися, чому фронтенд виріс з ~150 до ~385 КБ
- Розбори коду (навчання)

## Чекає на рішення власника

- Монетизація: ціни, підписка, платіжна система (ФОП → WayForPay/Monobank, без ФОП → Lemon Squeezy/Paddle)
- Платний Gemini, коли безкоштовного ліміту стане замало
- Render без засинання (~$7/міс)
- Власний домен (~$10–15/рік) — і адреса листів на ньому замість Gmail
- Ім'я власника / Impressum у Privacy Policy, якщо сайт стане комерційним

## Технічні нотатки

- Проєкт лежить у `~/Documents/vibeforge`
- Секрети тільки в `backend/.env` і `frontend/.env.local` (не в git) та в налаштуваннях Render/Vercel
- Схема бази: `backend/supabase/schema.sql` (запускати в Supabase SQL Editor)
- Таблиця `generations` навмисно без права видалення для сервера — тестові записи прибирати через SQL Editor
