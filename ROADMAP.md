# VibeForge — план роботи

## Де ми зараз (готово)

- **Веб-застосунок працює end-to-end**: React-чат зліва → FastAPI-бекенд → Gemini генерує повний HTML → живий прев'ю в iframe справа
- **Реальна AI-генерація** через безкоштовний рівень Google Gemini API (`GENERATOR=gemini`, ключ у `backend/.env` локально / у змінних середовища на Render)
  - Модель: `gemini-3.6-flash`
  - Автоматичні повторні спроби при тимчасовому 503 "high demand" від Google (до 5 разів)
  - Зрозуміле повідомлення користувачу при вичерпанні денної квоти (429), замість сирої помилки
  - Системний промпт забороняє localStorage/sessionStorage/cookies (не працюють у sandboxed iframe), вигадані шляхи до картинок (тільки inline SVG/CSS або picsum.photos), і просить сучасний, завершений дизайн замість "голого" HTML
- **Ітеративне редагування**: наступні повідомлення в чаті редагують вже наявний сайт, а не починають з нуля
- **Галерея проєктів**: список усіх створених сайтів на самому сайті, з можливістю відкрити або видалити
- **Завантаження готового сайту** як HTML-файлу
- **Опубліковано в інтернеті**: фронтенд на Vercel (`vibe-forge-swart.vercel.app`), бекенд на Render (`vibeforge-e0p3.onrender.com`), CORS налаштований через `FRONTEND_ORIGIN`
- Генератор схований за інтерфейсом (`GENERATOR=mock|gemini`), mock — для тестів без витрачання квоти

**Відомі обмеження:**
- Тільки **статичні односторінкові сайти** (HTML/CSS/JS в одному файлі, без бекенду) — свідомий вибір MVP
- Безкоштовний рівень Gemini: ліміт **20 генерацій/день** на проєкт (спільний для всіх користувачів сайту, скидається раз на добу) — після цього генерація недоступна до наступного дня
- Render (безкоштовний план) **не має постійного диска** — після засинання/перезапуску сервер втрачає всю історію проєктів; фронтенд це переживає, автоматично починаючи новий проєкт замість помилки, але старі проєкти зникають назавжди
- Render засинає після ~15 хв бездіяльності — перший запит після паузи виконується ~50 секунд (холодний старт)

## Наступні кроки (за пріоритетом)

1. **Продовжити промпт-інжиніринг** — оцінити результати нових правил (localStorage/картинки/дизайн) на живих прикладах, донастроїти за потреби
2. **Монетизація** — акаунти, ліміти генерацій, підписка (сюди ж — вирішення проблеми втрати проєктів: реальна БД замість JSON-файлу на ефемерному диску)

## Технічні борги

- Проєкт лежить у `~/Documents/vibeforge` (не плутати зі старим `~/Documents/ai-3d-forge` — два різні проєкти)
- Ключ Gemini у `backend/.env` (не в git) — якщо колись знадобиться новий, повтори процес отримання на aistudio.google.com/apikey
- Історія проєктів — JSON-файл на диску Render, який зникає при кожному перезапуску контейнера (безкоштовний план без постійного диска)
